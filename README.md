# Apple Tree Life Cycle Portal

The **Apple Tree Life Cycle Portal** hosts the natural life cycle, the orchard life cycle and the annual reproductive cycle. Stage and sub-stage characteristics are structured according to four dimensions. For orchard management operations, the portal integrates links to a list of relevant third-party databases and guidelines. For apple tree research, all references used throughout the life cycle are cited and traceable within the portal for further exploration and validation.

🔗 [https://applelifecycle-3094d65c1fea.herokuapp.com/](https://applelifecycle-3094d65c1fea.herokuapp.com/)

Contents: 57 stages · 487 management operations · 1,259 citations from 58 sources · 490 key measurements · 85 measurement protocols in 11 categories.

## Run locally

Requires Node 18+ and Docker.

```bash
npm install
cp .env.example .env      # already points at the local container
docker compose up -d db   # Postgres 15 on port 55432
npm start                 # http://localhost:3000/tree_lifecycle?env=orchard
```

Or `docker compose up` to run the app in a container too.

| Variable | |
|---|---|
| `DATABASE_URL` | Postgres connection string |
| `PGSSL` | `disable` for a local container; leave unset when hosted so TLS stays on |
| `PORT` | defaults to `3000` |

## How the database is built

`app/config/db.js` runs an ordered list of SQL files on every start: `database.sql` (references) → `natural.sql` (drops and recreates the stage tables, then seeds them) → `protocol.sql` (measurement protocols) → `added_operations_*.sql` (one pass per source) → `fix_*.sql` (link, timing and integrity corrections). Order matters, and each pass is idempotent.

The content tables are therefore **rebuilt from the SQL files on every boot** — anything written through the API at runtime is lost on restart. The SQL files are the source of truth.

`protocol.sql` is generated by `tools/build_protocol_sql.py`; edit the generator, not the file. `migrations/` holds standalone schema changes for an existing database.

## Editing `app/data/tablesData.json`

Each row links its operations with a `ref{STAGECODE}` marker. **An operation whose stage has no marker is invisible in the browser**, though valid in the database. When adding operations at a new stage, add the marker in the same change and check that the counts behind all markers still sum to the total operation count.

## Sources

Published orchard guides (Australian IPDM Manual, NSW Orchard Plant Protection Guide, Penn State, Oregon State, Midwest, New Jersey, Southeast US, APAL, *Apples: Botany, Production and Uses*), plus 17 operations cited to peer-reviewed papers by DOI covering replant decisions, sunburn mitigation and pollination.

Some publishers return `403` to automated requests while serving the same URL normally in a browser; those links are correct despite what a link checker reports.

## Deploy

Heroku container stack, built from `Dockerfile` via `heroku.yml`, deployed from `main`. Set `DATABASE_URL` and leave `PGSSL` unset. The server binds its port before running the SQL sequence, so a slow rebuild cannot cause a boot timeout.
